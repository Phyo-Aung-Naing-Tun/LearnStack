# Day 16: Nginx vs Apache & Install

Week 1–3 မှာ server ကို secure setup လုပ်ပြီး networking basics သင်ပြီးပါပြီ။ ဒီ week မှာတော့ **Nginx** web server ကို install လုပ်ပြီး domain အလိုက် site config လုပ်နည်း၊ static file serve လုပ်နည်း၊ PHP-FPM နဲ့ Node.js app တွေကို ချိတ်နည်း (Laravel/Nuxt deploy အတွက် foundation) တွေကို လေ့လာပါမယ်။

---

## Apache vs Nginx

| | Apache | Nginx |
|---|---|---|
| Architecture | Process/thread-based | Event-driven (async) |
| Concurrent connections | နည်းနည်း weaker | Traffic များတဲ့အခါ ပိုကောင်း |
| Static file serving | ကောင်း | ပိုမြန် |
| Reverse proxy | Module ထပ်လို | Built-in strength |
| Config style | `.htaccess` (per-directory) | Centralized config |

Modern web developer (Laravel/Nuxt) trend အနေနဲ့ Nginx ကို **reverse proxy + static file server** အနေနဲ့ ပိုသုံးကြပါတယ် — PHP-FPM (Laravel) နဲ့ Node.js process (Nuxt) ကို front မှာ ရပ်ပြီး traffic route လုပ်ပေးတာမျိုးအတွက် Nginx က သင့်တော်ပါတယ်။

---

## Nginx Install လုပ်ခြင်း

```bash
sudo apt update
sudo apt install nginx -y
```

### Service Status စစ်ခြင်း

```bash
sudo systemctl status nginx
```

`active (running)` ပြရင် install အောင်မြင်ပါပြီ။

### Firewall ဖွင့်ခြင်း (Week 3 က ufw)

```bash
sudo ufw allow 'Nginx Full'
```

> 💡 `Nginx Full` ဆိုတာ HTTP (80) နဲ့ HTTPS (443) နှစ်ခုလုံးကို allow လုပ်တာပါ။ HTTP ပဲ လိုရင် `'Nginx HTTP'` ကို သုံးနိုင်ပါတယ်။

### Browser ကနေ Test လုပ်ခြင်း

`http://your-server-ip` (သို့) domain point လုပ်ထားရင် `http://yourdomain.com` ကို ဝင်ကြည့်ပါ — **"Welcome to nginx!"** default page ပေါ်လာရင် install အောင်မြင်ပါပြီ။

---

## Nginx Service Commands

```bash
sudo systemctl start nginx      # စတင်
sudo systemctl stop nginx       # ရပ်
sudo systemctl restart nginx    # config အသစ်လိုချင်ရင် (downtime တစ်ခဏရှိ)
sudo systemctl reload nginx     # config reload (downtime မရှိ) — ပိုကောင်း
sudo nginx -t                   # config syntax စစ် (restart မလုပ်ခင် အမြဲစစ်ပါ)
sudo systemctl enable nginx     # server boot ဖြစ်တိုင်း auto-start
```

> **⚠️ အရေးကြီး:** Config file ပြင်တိုင်း `sudo nginx -t` နဲ့ syntax စစ်ပြီးမှ `reload` လုပ်ပါ — syntax error ပါတဲ့ config ကို တိုက်ရိုက် restart လုပ်ရင် Nginx service ရပ်သွားနိုင်ပြီး site အားလုံး down ဖြစ်သွားနိုင်ပါတယ်။

## Nginx Version & Info

```bash
nginx -v              # version ကြည့်
nginx -V              # compile options ပါ အသေးစိတ်ကြည့်
```

---

## Key Takeaways

- Nginx က event-driven architecture ကြောင့် concurrent connection အများကြီး handle လုပ်ဖို့ Apache ထက် ပိုကောင်းပါတယ်
- `systemctl reload` က downtime မရှိဘဲ config ပြောင်းနိုင်လို့ production မှာ `restart` ထက် ပိုသင့်တော်ပါတယ်
- Config ပြောင်းတိုင်း `nginx -t` syntax test — ဒါက production server ပေါ် အမြဲလုပ်ရမယ့် habit ပါ

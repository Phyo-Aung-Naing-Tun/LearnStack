# Day 6: Root User ဘာကြောင့် အန္တရာယ်များလဲ

Week 1 မှာ VPS ကို root user နဲ့ ဝင်ခဲ့ပါတယ်။ ဒါပေမဲ့ production server မှာ **root ကို တိုက်ရိုက်သုံးခြင်း** ဟာ security risk အကြီးအကျယ်ပါ။ ဒီ week မှာ server ကို attacker တွေရဲ့ target ဖြစ်နိုင်ခြေ လျော့ချဖို့ လိုအပ်တဲ့ setup တွေကို လုပ်သွားပါမယ်။

### Root User ရဲ့ ပြဿနာ

- Root account ရှိတယ်ဆိုတာ attacker တိုင်းသိပါတယ် — username guess လုပ်စရာမလိုတော့ဘူး၊ password ပဲ crack ရင်ရပြီ
- Root က permission အကန့်အသတ်မရှိလို့ command တစ်ခု မှားရိုက်မိရင် system တစ်ခုလုံး ပျက်စီးနိုင်တယ်
- Log ထဲမှာ "ဘယ်သူလုပ်တာလဲ" ခွဲခြားလို့ မရဘူး (team တစ်ခုနဲ့ share သုံးရင် ပိုပြဿနာ)

### Solution: Non-root User + sudo

`sudo` ဆိုတာ non-root user ကို "temporary root privilege" ပေးတဲ့ command ပါ။ Password ထပ်ရိုက်ရပြီး၊ log ထဲမှာ ဘယ်သူ ဘာလုပ်တယ်ဆိုတာ မှတ်တမ်းကျန်ပါတယ်။

### Non-root User အသစ် ဖန်တီးခြင်း

Server ကို root နဲ့ SSH ဝင်ပြီး:

```bash
adduser yourname
```

Password, name စတာတွေ မေးမှာပါ — ဖြည့်ပါ။

### sudo Privilege ပေးခြင်း

```bash
usermod -aG sudo yourname
```

- `-aG` = existing groups တွေကို ဖျက်မထားဘဲ `sudo` group ထဲထပ်ထည့်ခြင်း
- `sudo` group ထဲရောက်ရင် `sudo` command သုံးခွင့်ရပါတယ်

### Confirm လုပ်ခြင်း

```bash
su - yourname
sudo whoami
```

`root` လို့ ပြန်ပြရင် sudo အလုပ်လုပ်ပါပြီ။

**Checkpoint:** Password confirm ပြီး `root` ဆိုတဲ့ output ပေါ်လာရင် အောင်မြင်ပါပြီ။

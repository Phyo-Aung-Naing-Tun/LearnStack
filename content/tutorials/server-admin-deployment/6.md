# Day 6: Root User ဘာကြောင့် အန္တရာယ်များလဲ & User Management

Week 1 မှာ VPS ကို root user နဲ့ ဝင်ခဲ့ပါတယ်။ ဒါပေမဲ့ production server မှာ **root ကို တိုက်ရိုက်သုံးခြင်း** ဟာ security risk အကြီးအကျယ်ပါ။ ဒီ week မှာ server ကို attacker တွေရဲ့ target ဖြစ်နိုင်ခြေ လျော့ချဖို့ လိုအပ်တဲ့ setup တွေကို လုပ်သွားပါမယ်။

---

## Root User ရဲ့ ပြဿနာ

- Root account ရှိတယ်ဆိုတာ attacker တိုင်းသိပါတယ် — username guess လုပ်စရာမလိုတော့ဘူး၊ password ပဲ crack ရင်ရပြီ
- Root က permission အကန့်အသတ်မရှိလို့ command တစ်ခု မှားရိုက်မိရင် system တစ်ခုလုံး ပျက်စီးနိုင်တယ်
- Log ထဲမှာ "ဘယ်သူလုပ်တာလဲ" ခွဲခြားလို့ မရဘူး (team တစ်ခုနဲ့ share သုံးရင် ပိုပြဿနာ)

### Solution: Non-root User + sudo

`sudo` ဆိုတာ non-root user ကို "temporary root privilege" ပေးတဲ့ command ပါ။ Password ထပ်ရိုက်ရပြီး၊ log ထဲမှာ ဘယ်သူ ဘာလုပ်တယ်ဆိုတာ မှတ်တမ်းကျန်ပါတယ်။

---

## User ဖန်တီးခြင်း

### Non-root User အသစ် ဖန်တီးခြင်း

Server ကို root နဲ့ SSH ဝင်ပြီး:

```bash
adduser yourname
```

Password, name စတာတွေ မေးမှာပါ — ဖြည့်ပါ။

> 💡 `adduser` နဲ့ `useradd` ကွာခြားချက် — `adduser` က interactive ဖြစ်ပြီး home directory, password အစဉ်တစ်ဆိုက် setup လုပ်ပေးပါတယ်။ `useradd` ကတော့ low-level command ဖြစ်ပြီး manually option တွေ ထည့်ပေးရပါတယ်။ `adduser` ပိုလွယ်ပါတယ်။

### useradd နဲ့ ဖန်တီးချင်ရင်

```bash
# Home directory နဲ့ bash shell ပါတဲ့ user ဖန်တီး
sudo useradd -m -s /bin/bash yourname

# Password သတ်မှတ်
sudo passwd yourname
```

| Option | ဘာလုပ်လဲ |
|---|---|
| `-m` | Home directory (`/home/yourname`) ဖန်တီး |
| `-s /bin/bash` | Default shell ကို bash သတ်မှတ် |
| `-c "Full Name"` | User ရဲ့ full name/comment ထည့် |
| `-e 2027-01-01` | Account expiry date သတ်မှတ် |

---

## sudo Privilege ပေးခြင်း

```bash
usermod -aG sudo yourname
```

- `-aG` = existing groups တွေကို ဖျက်မထားဘဲ `sudo` group ထဲ ထပ်ထည့်ခြင်း
- `sudo` group ထဲရောက်ရင် `sudo` command သုံးခွင့်ရပါတယ်

### Confirm လုပ်ခြင်း

```bash
su - yourname
sudo whoami
```

`root` လို့ ပြန်ပြရင် sudo အလုပ်လုပ်ပါပြီ။

**Checkpoint:** Password confirm ပြီး `root` ဆိုတဲ့ output ပေါ်လာရင် အောင်မြင်ပါပြီ။

---

## User Information ကြည့်ခြင်း

### Current User စစ်ပါ

```bash
whoami           # လက်ရှိ login ဝင်နေတဲ့ user name
id               # uid, gid, groups အားလုံး ပြ
id yourname      # သတ်မှတ်ထားတဲ့ user ရဲ့ info ကြည့်
```

### System User တွေ အားလုံးကြည့်ပါ

```bash
# /etc/passwd ကို ဖတ် (user database)
cat /etc/passwd

# Human-created user တွေ ပဲ filter (UID 1000+)
awk -F: '$3 >= 1000 {print $1, $3, $6, $7}' /etc/passwd
```

`/etc/passwd` format: `username:x:uid:gid:comment:home:shell`

### Login ဝင်နေတဲ့ User တွေ ကြည့်ပါ

```bash
who          # လောလောဆယ် login ဝင်နေသူတွေ
w            # login ဝင်နေသူ + activity ပြ
last         # နောက်ဆုံး login history
last yourname  # specific user ရဲ့ login history
```

---

## Group Management

Linux မှာ user တစ်ယောက်ဟာ groups အများကြီး ပိုင်ဆိုင်နိုင်ပါတယ်။ Group ကနေ file/resource access ကို ခွဲခြားပါတယ်။

### Group တွေ ကြည့်ပါ

```bash
groups yourname          # user ရဲ့ group list
cat /etc/group           # system group အားလုံး
getent group sudo        # sudo group ထဲ ဘယ်သူပါလဲ
```

### Group အသစ် ဖန်တီးခြင်း

```bash
sudo groupadd developers
sudo groupadd deploy
```

### User ကို Group ထဲ ထည့်ခြင်း

```bash
# Single group ထည့်
sudo usermod -aG developers yourname

# Multiple groups တစ်ချိန်တည်း ထည့်
sudo usermod -aG developers,deploy yourname
```

> ⚠️ `-a` (append) မပါရင် existing groups တွေ ကျန်ခဲ့ပြီး ထည့်တဲ့ group ပဲ ကျန်မှာပါ — `-aG` ကိုပဲ အမြဲသုံးပါ။

### User ကို Group ကနေ ဖြုတ်ပါ

```bash
sudo gpasswd -d yourname developers
```

### Group ဖျက်ပါ

```bash
sudo groupdel developers
```

---

## sudo Configuration (Fine-grained Control)

`/etc/sudoers` file ကို တိုက်ရိုက် edit မလုပ်ပါနဲ့ — `visudo` ကို သုံးပါ (syntax error check ပါတဲ့)။

```bash
sudo visudo
```

### Specific Command ကို ပဲ sudo ခွင့်ပေးခြင်း

```bash
# yourname ကို nginx reload ကိုပဲ sudo သုံးခွင့်ပေး
yourname ALL=(ALL) NOPASSWD: /bin/systemctl reload nginx
```

### sudo log ကြည့်ခြင်း

```bash
sudo grep sudo /var/log/auth.log | tail -20
```

ဘယ် user က ဘာ command ကို sudo နဲ့ run ခဲ့တာလဲ audit လုပ်နိုင်ပါတယ်။

## User Account ပြောင်းလဲခြင်း

### Password ပြောင်းပါ

```bash
passwd              # ကိုယ့် password ပြောင်း
sudo passwd yourname  # တခြား user ရဲ့ password ပြောင်း (root only)
```

### Username ပြောင်းပါ

```bash
sudo usermod -l newname oldname
```

### Home Directory ပြောင်းပါ

```bash
sudo usermod -d /home/newdir -m yourname
```

### Shell ပြောင်းပါ

```bash
sudo chsh -s /bin/bash yourname    # bash
sudo chsh -s /bin/zsh yourname     # zsh
sudo chsh -s /usr/sbin/nologin yourname  # login ပိတ်
```

---

## User Account Lock & Unlock

Temporary block လုပ်ဖို့ (delete မလုပ်ဘဲ):

```bash
# Account lock (password login ပိတ်)
sudo usermod -L yourname
sudo passwd -l yourname    # alternative

# Account unlock
sudo usermod -U yourname
sudo passwd -u yourname    # alternative

# Lock ဖြစ်မဖြစ် စစ်
sudo passwd -S yourname
# Output: yourname L ... (L = locked, P = active, NP = no password)
```

> 💡 Account lock လုပ်ထားရင် SSH key login က ဆက်အလုပ်လုပ်နိုင်ပါတယ် — SSH key ကိုပါ ပိတ်ဖို့ `authorized_keys` ကို ဖျက်ရပါမယ်။

---

## User ဖျက်ခြင်း

### userdel Command

```bash
# User ဖျက် (home directory ထားခဲ့)
sudo userdel yourname

# User + home directory + mail spool အတူ ဖျက်
sudo userdel -r yourname
```

| Option | ဘာလုပ်လဲ |
|---|---|
| (none) | `/etc/passwd` မှ user ဖျက်၊ home dir ထားခဲ့ |
| `-r` | Home directory (`/home/yourname`) + mail spool ပါ ဖျက် |
| `-f` | User login ဝင်နေတဲ့အချိန် force delete (အန္တရာယ်ရှိ) |

---

### Delete မလုပ်ခင် Pre-Deletion Checklist

User ဖျက်ခြင်းကို reversible မဟုတ်တာကြောင့် ဒီ step တွေကို အရင် လုပ်ပါ:

**1. User login ဝင်နေမနေ စစ်ပါ**

```bash
who | grep yourname
w | grep yourname
```

Output မပေါ်ရင် login မဝင်နေပါဘူး — ဖျက်ဖို့ safe ပါပြီ။

**2. User ပိုင်တဲ့ process တွေ စစ်ပါ**

```bash
ps aux | grep yourname
```

Run နေတဲ့ process ရှိရင် kill လုပ်ပါ:

```bash
sudo pkill -u yourname
```

**3. User ပိုင်တဲ့ file တွေ စစ်ပါ**

```bash
# System တစ်ခုလုံးထဲ user ပိုင် file ရှာ
sudo find / -user yourname -ls 2>/dev/null

# Home directory ထဲ ဘာတွေ ရှိလဲ ကြည့်
ls -la /home/yourname/
```

**4. Cron jobs စစ်ပါ**

```bash
sudo crontab -u yourname -l
```

**5. Account ကို Lock ဦးသောက်ပြီး နေ့အနည်းငယ် ကြည့်ပါ**

```bash
sudo usermod -L yourname
```

ပြဿနာ မရှိမှ delete လုပ်ပါ။

---

### Safe Deletion Workflow

```bash
# Step 1: Account lock
sudo usermod -L yourname

# Step 2: Home directory backup (လိုရင်)
sudo tar -czf /backup/yourname-$(date +%F).tar.gz /home/yourname/

# Step 3: Run နေတဲ့ process kill
sudo pkill -u yourname

# Step 4: User delete
sudo userdel -r yourname

# Step 5: Delete ဖြစ်သွားတာ စစ်
id yourname   # "no such user" ပေါ်ရင် အောင်မြင်
```

---

### User ဖျက်ပြီးနောက် Orphaned Files

User ဖျက်ပြီးရင် ထို user ဖန်တီးခဲ့တဲ့ file တွေ ownership မရှိတော့ဘဲ UID number ပဲ ကျန်ပါတယ်:

```bash
# Orphaned file (owner မရှိတာ) တွေ ရှာပါ
sudo find / -nouser -ls 2>/dev/null
```

ဒီ file တွေကို:

```bash
# တခြား user ကို ownership ပြောင်းပေး
sudo chown newowner /path/to/file

# သို့မဟုတ် ဖျက်ပစ်
sudo rm /path/to/orphaned-file
```

---

### User ဖျက်ခြင်း vs Lock လုပ်ခြင်း

| | `userdel -r` | `usermod -L` |
|---|---|---|
| Data | ဆုံးရှုံး | ကျန်ရှိ |
| Reversible | မဟုတ် | ✅ ဖြစ် |
| Use case | Account မလိုတော့ဘဲ သေချာရင် | Temporary suspension |
| Production | ⚠️ ဆင်ခြင်မှ လုပ်ပါ | ✅ Recommended |

> ⚠️ Production server မှာ user delete မလုပ်ခင် — backup လုပ်ပြီး `lock` နဲ့ ကြည့်ကာ သေချာမှ delete လုပ်ပါ၊ home directory delete ဖြစ်သွားရင် data ပြန်မရနိုင်ပါ။

## User Management Best Practices

| အလေ့အကျင့် | ရှင်းလင်းချက် |
|---|---|
| Root login ပိတ် | SSH config မှာ `PermitRootLogin no` (Day 8 မှာ ပြောပါမယ်) |
| User တစ်ယောက်ချင်းစီ account | Account share မလုပ်ပါနဲ့ — audit trail ပျောက်တယ် |
| Least privilege | User တစ်ယောက်ကို လိုတာပဲ ပေး — sudo ကို ပေးလွန်မနေပါနဲ့ |
| Regular audit | `last`, `who`, `sudo log` ကို ပုံမှန်စစ်ပါ |
| Strong password | `passwd` policy enforce လုပ်ချင်ရင် `libpam-pwquality` install |
| Temp user ကို lock | Contract ပြီးရင် account delete မဟုတ်ဘဲ `usermod -L` |

## Quick Reference

```bash
adduser name              # User ဖန်တီး (interactive)
usermod -aG sudo name     # sudo ပေး
usermod -aG group name    # group ထည့်
gpasswd -d name group     # group ကနေ ဖြုတ်
usermod -L name           # account lock
usermod -U name           # account unlock
userdel -r name           # user + home ဖျက်
id name                   # user info ကြည့်
groups name               # group list ကြည့်
last name                 # login history ကြည့်
```

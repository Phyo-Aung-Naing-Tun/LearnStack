# Day 17: Nginx Config Structure & Server Block

ဒီနေ့မှာ Nginx config file တွေ ဘယ်မှာ ရှိလဲ နားလည်ပြီး domain တစ်ခုအတွက် server block တစ်ခု ဖန်တီးနည်း လေ့လာပါမယ်။

---

## Config File Location

```
/etc/nginx/
├── nginx.conf              # main config (global settings)
├── sites-available/        # site config တွေ သိမ်းထားတဲ့နေရာ
├── sites-enabled/          # active ဖြစ်နေတဲ့ site တွေ (symlink)
└── conf.d/                 # additional global configs
```

> 💡 **sites-available vs sites-enabled:** `sites-available` ထဲမှာ config file တွေ ရေးပြီး `sites-enabled` ထဲကို symlink (shortcut) လုပ်မှ Nginx က ဖတ်ပါတယ်။ ဒီနည်းနဲ့ site ကို enable/disable လုပ်ဖို့ လွယ်ကူပါတယ်။

### Main Config Overview

```bash
cat /etc/nginx/nginx.conf
```

`nginx.conf` ထဲမှာ `include /etc/nginx/sites-enabled/*;` ဆိုတဲ် line ပါတာကြောင့် `sites-enabled` ထဲက config တွေကို auto-load လုပ်ပါတယ်။

---

## Server Block (Virtual Host) ဆိုတာဘာလဲ

Server block တစ်ခုက **domain/subdomain တစ်ခုအတွက် config** ပါ။ Server တစ်ခုတည်းပေါ်မှာ domain အများကြီး host လုပ်ချင်ရင် server block အများကြီး ဖန်တီးလို့ရပါတယ်။ Apache မှာ "virtual host" လို့ ခေါ်ပြီး Nginx မှာ "server block" လို့ ခေါ်ပါတယ်။

---

## Static Site အတွက် Server Block ဖန်တီးခြင်း

### Step 1: Config File ဖန်တီးပါ

```bash
sudo nano /etc/nginx/sites-available/myapp.com
```

```nginx
server {
    listen 80;
    listen [::]:80;

    server_name myapp.com www.myapp.com;
    root /var/www/myapp.com/html;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

**Directive တစ်ခုချင်းစီ ရှင်းလင်းချက်:**

| Directive | ဘာလုပ်လဲ |
|---|---|
| `listen 80` | HTTP port 80 မှာ listen |
| `listen [::]:80` | IPv6 ကိုပါ support |
| `server_name` | ဘယ် domain(s) အတွက်လဲ |
| `root` | Static file တွေ ဘယ် folder ထဲမှာလဲ |
| `index` | Default file (index.html) |
| `try_files` | Request လာတဲ့ file ကို ရှာ၊ မတွေ့ရင် 404 |

### Step 2: Site Enable လုပ်ပါ (Symlink)

```bash
sudo ln -s /etc/nginx/sites-available/myapp.com /etc/nginx/sites-enabled/
```

### Step 3: Default Site ဖျက်ပါ (Optional)

```bash
sudo rm /etc/nginx/sites-enabled/default
```

Default site ကို ဖျက်မှ သင့် custom site က port 80 ကို ရပါမယ်။

### Step 4: Config Test & Reload

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### Step 5: Web Root Folder ဖန်တီးပါ

```bash
sudo mkdir -p /var/www/myapp.com/html
echo "<h1>Hello from myapp.com</h1>" | sudo tee /var/www/myapp.com/html/index.html
sudo chown -R www-data:www-data /var/www/myapp.com
sudo chmod -R 755 /var/www/myapp.com
```

> 💡 `www-data` က Nginx process run တဲ့ user ပါ။ Web root folder ကို `www-data` owner ပေးမှ Nginx ဖတ်လို့ ရပါတယ်။

Browser ကနေ domain ဝင်ကြည့်ပြီး "Hello from myapp.com" ပေါ်ရင် server block အောင်မြင်ပါပြီ။

---

## Symlink စစ်နည်း

```bash
ls -la /etc/nginx/sites-enabled/
```

Output မှာ `myapp.com -> /etc/nginx/sites-available/myapp.com` ဆိုတာမျိုး ပေါ်ရင် symlink မှန်ပါပြီ။

---

## Key Takeaways

- `sites-available` = config သိမ်းတဲ့နေရာ၊ `sites-enabled` = active config (symlink)
- Server block တစ်ခုနဲ့ domain တစ်ခု manage — server တစ်ခုတည်းပေါ်မှာ domain အများကြီး host လုပ်နိုင်
- Web root folder ကို `www-data` user ပိုင်ဆိုင်အောင် `chown` လုပ်ဖို့ မမေ့ပါနဲ့

# Day 19: Nuxt (Node.js) ကို Reverse Proxy ချိတ်ခြင်း

ဒီနေ့မှာ Nginx ကို **reverse proxy** အနေနဲ့ သုံးပြီး Nuxt SSR app ကို domain ကနေ serve လုပ်နည်း လေ့လာပါမယ်။

---

## Reverse Proxy ဆိုတာဘာလဲ

Static file serve လုပ်တဲ့ PHP နဲ့မတူဘဲ Nuxt SSR app က **Node.js process တစ်ခု run နေရပါတယ်** (ဥပမာ port 3000 မှာ)။ Nginx ကို "front door" အနေနဲ့ ထားပြီး internal Node process ဆီ traffic ကို route (proxy) လုပ်ပေးရတာကို **reverse proxy** လို့ ခေါ်ပါတယ်။

```
Internet → Nginx (port 80/443) → Node.js Process (port 3000, localhost only)
```

ဒီနည်းနဲ့:
- Node process ကို internet ကနေ တိုက်ရိုက် access မဝင်နိုင် (security)
- Nginx က SSL termination, caching, compression handle လုပ်နိုင်
- Server တစ်ခုတည်းမှာ Node app အများကြီး host လုပ်နိုင်

---

## Nuxt App အတွက် Server Block

```bash
sudo nano /etc/nginx/sites-available/nuxt-app.com
```

```nginx
server {
    listen 80;
    server_name nuxt-app.com www.nuxt-app.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

---

## Config Directive တစ်ခုချင်းစီ ရှင်းလင်းချက်

| Directive | ဘာလုပ်လဲ |
|---|---|
| `proxy_pass http://127.0.0.1:3000` | Request ကို localhost port 3000 (Node app) ဆီ forward |
| `proxy_http_version 1.1` | HTTP/1.1 သုံး (WebSocket support လိုတာကြောင့်) |
| `Upgrade` + `Connection 'upgrade'` | WebSocket connection upgrade support (Nuxt HMR/live features) |
| `Host $host` | Original domain name ကို Node app ကို pass |
| `proxy_cache_bypass $http_upgrade` | WebSocket request တွေကို cache မလုပ်ဘဲ pass |
| `X-Real-IP` | Original client IP ကို Node app ကို ပို့ |
| `X-Forwarded-For` | Proxy chain ထဲက IP list ကို Node app ကို ပို့ |
| `X-Forwarded-Proto` | HTTP/HTTPS ဘယ်ဟာလဲ Node app ကို အသိပေး |

> 💡 `X-Forwarded-For` Header မပါရင် Node app မှာ `req.ip` ကို ကြည့်တဲ့အခါ client real IP မမြင်ဘဲ `127.0.0.1` (Nginx IP) ပဲ မြင်ရပါလိမ့်မယ်။

## Enable & Test

```bash
sudo ln -s /etc/nginx/sites-available/nuxt-app.com /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

---

## Nuxt App ကို Test Run လုပ်ကြည့်ပါ

Nuxt app folder ထဲဝင်ပြီး:

```bash
# Build (production)
npm run build

# Run (port 3000 မှာ)
node .output/server/index.mjs
```

ဒါမှမဟုတ် development mode:

```bash
npm run dev -- --port 3000
```

> **မှတ်ချက်:** Terminal ပိတ်ရင် Node process လည်း ရပ်သွားပါတယ်။ Production မှာ **PM2** process manager သုံးပြီး background run ထားဖို့ လိုပါတယ် — Week 6 မှာ အသေးစိတ် ပြောပါမယ်။

## Multiple Ports မှာ App များ Run ခြင်း

App အများကြီး run ချင်ရင် port ခွဲပေးပါ:

```nginx
# nuxt-app.com → port 3000
proxy_pass http://127.0.0.1:3000;

# another-app.com → port 3001
proxy_pass http://127.0.0.1:3001;
```

Port တွေ `ufw` နဲ့ public ကနေ block ထားဖို့ မမေ့ပါနဲ့ (Nginx ကနေ proxy လုပ်မှာမို့ public open မလုပ်ရ):

```bash
# Node ports တွေကို public ကနေ ပိတ်
sudo ufw deny 3000
sudo ufw deny 3001
```

---

## Key Takeaways

- Reverse proxy = Nginx က client request ကို internal service ဆီ forward လုပ်တာ
- Node.js app တွေကို port 3000+ မှာ run ပြီး Nginx ကနေ proxy လုပ်
- `X-Forwarded-*` headers တွေ pass လုပ်မှ Node app မှာ real client info ရပါတယ်
- Node ports တွေကို firewall နဲ့ block ထားပြီး Nginx ကနေ ပဲ ဖြတ်ပါ (security)

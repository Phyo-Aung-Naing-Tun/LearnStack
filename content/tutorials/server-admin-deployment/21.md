# Day 21: Nginx User Management & Process Security

ဒီနေ့မှာ Nginx က ဘယ် user အနေနဲ့ run တာလဲ နားလည်ပြီး web server user management ကို security အတွက် ဘယ်လို configure လုပ်ရမလဲ လေ့လာပါမယ်။

---

## Nginx User ဆိုတာဘာလဲ

Linux မှာ process တိုင်း ကိုယ်ပိုင် user account နဲ့ run ပါတယ်။ Nginx ရဲ့ worker processes တွေ **`www-data`** user အနေနဲ့ run ပါတယ် (Ubuntu/Debian မှာ)။ ဒါဟာ security principle တစ်ခုဖြစ်တဲ့ **principle of least privilege** ကို implement လုပ်တာပါ — Nginx process က root ဖြစ်ရင် exploit ခံရတဲ့အခါ server တစ်ခုလုံး compromise ဖြစ်သွားနိုင်ပါတယ်။

---

## Nginx Process Architecture

```bash
# Nginx processes ကြည့်
ps aux | grep nginx
```

Output:
```
root     12345  0.0  0.0  nginx: master process
www-data 12346  0.0  0.1  nginx: worker process
www-data 12347  0.0  0.1  nginx: worker process
```

- **Master process** — `root` user နဲ့ run (port 80/443 bind လုပ်ဖို့ root privilege လိုတာကြောင့်)
- **Worker processes** — `www-data` user နဲ့ run (actual request handle လုပ်တာ)

---

## Nginx User Configuration

### Main Config ကြည့်ပါ

```bash
sudo nano /etc/nginx/nginx.conf
```

File ရဲ့ ထိပ်ဆုံးမှာ:

```nginx
user www-data;
worker_processes auto;
```

- `user www-data` — worker process run မယ့် user ကို သတ်မှတ်
- `worker_processes auto` — CPU core count အလိုက် worker process count auto-set

### Worker Process Count Manual Set

```bash
# CPU core count စစ်
nproc

# သို့မဟုတ်
grep processor /proc/cpuinfo | wc -l
```

```nginx
worker_processes 2;  # 2-core server အတွက်
```

## www-data User ဆိုတာဘာလဲ

`www-data` က web server (Nginx, Apache) အတွက် system က auto-create လုပ်ပေးတဲ့ **system user** ပါ:

```bash
# www-data user info ကြည့်
id www-data
# uid=33(www-data) gid=33(www-data) groups=33(www-data)

# User ရဲ့ home directory စစ်
grep www-data /etc/passwd
# www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
```

> 💡 `nologin` ဆိုတာ ဒီ user နဲ့ SSH login ဝင်လို့ မရ — web server ပဲ သုံးနိုင်တာ (security feature)

## File Ownership & Nginx

### Web Root Ownership ဘယ်လို သတ်မှတ်ရမလဲ

```bash
# Web files တွေကို www-data ပိုင်ဆိုင်အောင်
sudo chown -R www-data:www-data /var/www/

# Permission check
ls -la /var/www/
```

### Permission Best Practices

| File Type | Recommended Permission | ရှင်းလင်းချက် |
|---|---|---|
| Directories | `755` | Owner = rwx, Others = r-x |
| Static files | `644` | Owner = rw, Others = r-- |
| Laravel storage/ | `775` | www-data write access လို |
| `.env` file | `640` | Owner + group ပဲ ဖတ်နိုင် |
| Private keys | `600` | Owner ပဲ ဖတ်နိုင် |

```bash
# General web files
sudo chmod -R 755 /var/www/myapp.com/
sudo chmod -R 644 /var/www/myapp.com/html/*.html

# Laravel specific
sudo chmod -R 775 /var/www/laravel-app/storage
sudo chmod -R 775 /var/www/laravel-app/bootstrap/cache
sudo chmod 640 /var/www/laravel-app/.env
```

## Developer User + www-data Group (Best Practice)

Production server မှာ file တွေကို edit လုပ်ဖို့ developer user (ဥပမာ `deploy`) ကို `www-data` group ထဲ ထည့်ပေးတဲ့ pattern ကို သုံးကြပါတယ်:

```bash
# deploy user ဖန်တီး
sudo adduser deploy

# deploy user ကို www-data group ထဲ ထည့်
sudo usermod -aG www-data deploy

# Group change verify
groups deploy
# deploy : deploy www-data
```

ပြီးရင် web root ကို:

```bash
# Owner = deploy, Group = www-data
sudo chown -R deploy:www-data /var/www/laravel-app/

# Directory: owner+group can write, others read-only
sudo chmod -R 2775 /var/www/laravel-app/
```

> 💡 `2775` ထဲက `2` က **setgid bit** ပါ — ဒီ folder ထဲ ဖန်တီးတဲ့ file/folder တိုင်း parent group (`www-data`) ကို inherit လုပ်မှာပါ၊ ownership ကို တစ်ခုချင်းစီ `chown` မလုပ်ရဘဲ အဆင်ပြေပါတယ်။

## PHP-FPM User Configuration

PHP-FPM ကလည်း ကိုယ်ပိုင် user/group settings ရှိပါတယ်:

```bash
sudo nano /etc/php/8.3/fpm/pool.d/www.conf
```

```ini
[www]
user = www-data
group = www-data
listen.owner = www-data
listen.group = www-data
```

Laravel app တစ်ခုချင်းစီအတွက် **separate PHP-FPM pool** ဖန်တီးလို့ရပါတယ် (security isolation):

```bash
sudo cp /etc/php/8.3/fpm/pool.d/www.conf /etc/php/8.3/fpm/pool.d/laravel-app.conf
sudo nano /etc/php/8.3/fpm/pool.d/laravel-app.conf
```

```ini
[laravel-app]
user = deploy
group = www-data
listen = /var/run/php/php8.3-fpm-laravel.sock
listen.owner = www-data
listen.group = www-data
```

ပြီးရင် Nginx server block မှာ socket path ပြောင်းပါ:

```nginx
fastcgi_pass unix:/var/run/php/php8.3-fpm-laravel.sock;
```

## Security Audit Commands

```bash
# www-data ပိုင်တဲ့ file/folder တွေ စစ်
find /var/www -user www-data -ls

# world-writable file/folder တွေ စစ် (လုံခြုံရေး risk)
find /var/www -perm -002 -ls

# SUID bit ပါတဲ့ file တွေ စစ်
find /var/www -perm /4000 -ls

# Nginx run နေတဲ့ user စစ်
ps aux | grep "nginx: worker"
```

## Nginx Worker Connections Tuning

```bash
sudo nano /etc/nginx/nginx.conf
```

```nginx
events {
    worker_connections 1024;  # worker တစ်ခု handle နိုင်တဲ့ max connection
    multi_accept on;           # multiple connection ကို တစ်ချိန်တည်း accept
    use epoll;                 # Linux မှာ efficient event model
}
```

**Max theoretical connections** = `worker_processes × worker_connections`

```
2 workers × 1024 connections = 2048 max concurrent connections
```

## Nginx Logging User Actions

Nginx access log ထဲမှာ request info ပါပါတယ် — ဘယ် IP ကနေ ဘာ request ပေးပို့တာလဲ:

```bash
sudo tail -f /var/log/nginx/access.log
```

Output format:
```
192.168.1.1 - - [04/Sep/2026:23:00:00 +0630] "GET /index.html HTTP/1.1" 200 1234 "-" "Mozilla/5.0..."
```

| Field | ဘာလဲ |
|---|---|
| `192.168.1.1` | Client IP |
| `200` | HTTP status code |
| `1234` | Response size (bytes) |
| `"Mozilla/5.0..."` | User agent (browser/client info) |

## Key Takeaways

- Nginx master process က `root`၊ worker processes တွေက `www-data` (least privilege)
- Web files တွေကို `www-data` group ပိုင်ဆိုင်မှ Nginx ဖတ်လို့ ရပါတယ်
- Developer user ကို `www-data` group ထဲ ထည့်ပြီး `setgid (2775)` pattern သုံးတာ production best practice
- PHP-FPM ကို app တစ်ခုချင်းစီအတွက် separate pool ဖန်တီးရင် security isolation ပိုကောင်းပါတယ်
- `world-writable` file တွေကို regular audit လုပ်ပါ

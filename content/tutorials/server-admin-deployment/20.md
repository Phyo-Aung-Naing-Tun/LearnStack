# Day 20: Multiple Sites & Common Troubleshooting

ဒီနေ့မှာ server တစ်ခုတည်းပေါ်မှာ site အများကြီး host လုပ်နည်း၊ error တွေကို log file ကနေ debug လုပ်နည်းနဲ့ Week 4 checklist ကို ပြန်စစ်ပါမယ်။

---

## Server တစ်ခုတည်းပေါ်မှာ Site အများကြီး Host လုပ်ခြင်း

Server block တစ်ခုချင်းစီမှာ `server_name` ကွဲပြားထားရင် Nginx က domain အလိုက် automatic ခွဲပေးပါတယ်:

```
/etc/nginx/sites-available/
├── laravel-app.com      # PHP/Laravel site
├── nuxt-app.com         # Node.js/Nuxt SSR site
└── static-site.com      # Static HTML site
```

Site အသစ်တစ်ခုချင်းစီအတွက် ဒီ step တွေ ပြုလုပ်ရပါတယ်:

```bash
# 1. Config file ဖန်တီး
sudo nano /etc/nginx/sites-available/new-site.com

# 2. Symlink လုပ်ပြီး enable
sudo ln -s /etc/nginx/sites-available/new-site.com /etc/nginx/sites-enabled/

# 3. Syntax test
sudo nginx -t

# 4. Reload
sudo systemctl reload nginx
```

## Common Errors & Fix

| Error | Cause | Fix |
|---|---|---|
| **502 Bad Gateway** | Node app run မနေဘူး / PHP-FPM socket မှား | `pm2 status` (Node) သို့ `systemctl status php8.3-fpm` စစ် |
| **404 Not Found** | `root` path မှား / `try_files` config မှား | `root` directive ကို double-check |
| **403 Forbidden** | File permission (owner/chmod) မှား | `chown -R www-data:www-data` စစ် |
| **Site အသစ် မထင်ဘူး** | `sites-enabled` ထဲ symlink မလုပ်ရသေး | `ln -s` step ပြန်စစ် |
| **Config reload fail** | Syntax error ရှိတယ် | `sudo nginx -t` run ပြီး error message ကြည့် |

### 502 Bad Gateway Debug

```bash
# PHP-FPM စစ်
sudo systemctl status php8.3-fpm

# Socket file ရှိမရှိ စစ်
ls -la /var/run/php/

# Node app run နေမနေ စစ်
sudo ss -tulpn | grep 3000
```

### 403 Forbidden Debug

```bash
# File/folder permission စစ်
ls -la /var/www/myapp.com/

# Owner ပြင်
sudo chown -R www-data:www-data /var/www/myapp.com/

# Permission ပြင်
sudo chmod -R 755 /var/www/myapp.com/
```

## Log File ကြည့်ခြင်း (Debug အရေးကြီးဆုံး Tool)

```bash
# Global error log (real-time)
sudo tail -f /var/log/nginx/error.log

# Global access log (request တွေ monitor)
sudo tail -f /var/log/nginx/access.log

# နောက်ဆုံး 50 line ကြည့်
sudo tail -50 /var/log/nginx/error.log
```

### Site-Specific Log သတ်မှတ်ခြင်း

Server block ထဲမှာ ထည့်ပါ:

```nginx
server {
    ...
    access_log /var/log/nginx/myapp.com.access.log;
    error_log /var/log/nginx/myapp.com.error.log;
}
```

Site-specific log သုံးရင် ဘယ် site ကနေ error ဖြစ်တာလဲ ရှာရ ပိုလွယ်ပါတယ်။

## Nginx Config Debugging Tips

### Active Config စစ်ပါ

```bash
# Sites enabled ကြည့်
ls -la /etc/nginx/sites-enabled/

# Config dump (Nginx ဖတ်မယ့် config အားလုံး)
sudo nginx -T

# Specific file syntax စစ်
sudo nginx -t -c /etc/nginx/nginx.conf
```

### Default Server Block ဘာဖြစ်မလဲ

`server_name` match မဖြစ်တဲ့ request တွေ (ဥပမာ direct IP access) default server ဆီ ရောက်ပါတယ်:

```nginx
# Default server block (ဘာ domain မှ match မဖြစ်တာ ဒီမှာ ကျ)
server {
    listen 80 default_server;
    server_name _;
    return 444;  # Connection ပိတ်ပစ် (ဘာ response မှ မပေး)
}
```
